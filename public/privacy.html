Minimal data by design.

What the application processes

Pump War Room does not require an account, wallet, private key, payment, advertising identifier, or analytics cookie. Questions submitted to the local analyst are processed to answer the request and are not written to the application database.

Hosting and network infrastructure may temporarily process ordinary request metadata—such as IP address, user agent, timestamp, requested path, status code, and a request identifier—for delivery, reliability, abuse prevention, and security. Infrastructure providers may retain operational logs under their own policies.

Browser-local preferences

Watchlists and named filter lenses are stored in this origin’s browser-local localStorage, with bounded JSON export and import. They are not written to the application database, are not an authenticated or cross-device service, and may disappear when you clear site data or use a browser that blocks storage. Opening a watched coin or comparison still sends the requested public mint in the ordinary request path, which infrastructure logs may temporarily process as described above.

Optional Telegram delivery

If the operator configures Telegram, the application sends bounded material-event text, a public mint, evidence class and timestamp, a short event identifier, and a read-only dossier link through the official Telegram Bot API to the operator-configured chat. Browser-local watchlists do not subscribe, unsubscribe, or select that delivery. Bot credentials and the destination identifier remain environment configuration: they are not persisted in SQLite or exposed by public health, snapshot, or timeline APIs. The restart-safe outbox retains aggregate status, bounded error codes, attempt times, and Telegram’s returned message identifier; these per-alert delivery fields and dedupe keys are not public. Ambiguous network, malformed-success, and HTTP 5xx results receive four bounded retries before dead-lettering on the fifth attempt; ambiguous sends can be duplicated because the Bot API has no client idempotency key.

Market data

The application stores public token identifiers, derived outcome metrics, allowlisted holder/developer scalars, domain-separated hashes of selected public identity fields, and minimal provenance. Normalized handles, registrable website domains, names, and symbols used for matching are not retained. Its provider-ingestion path does not persist or expose bulk GeckoTerminal responses, candle series, provider prices or volumes, descriptions, images, raw social profiles, or unrecognized provider fields. Public API responses expose duplicate counts, bounded acquisition states, and evidence limitations, not stored digests or raw provider errors. Server-side provider requests contain public token and pool identifiers, not user account or wallet data.

Identity review data

The operator-only canonical registry stores public mint identifiers, bounded display labels, typed variant and relationship codes, evidence classes, timestamps, deterministic proposal keys, and append-only review decisions. Automated collision evidence stores allowlisted method labels and counts, not raw social profiles, credentials, private keys, cookies, or provider payloads. Proposed edges remain visibly separate from reviewed facts. The public resolver accepts one exact mint and exposes no write operation; registry imports and decisions require local database access.

Opaque Actor labels

A random 32-byte installation secret and domain-separated keyed digests create per-installation keyed Actor labels that replace public wallet and third-party source-profile identities with stable opaque Actor N values. Public snapshot, dossier, timeline, SSE, analyst, UI, and export surfaces do not expose raw creator, deployer, wallet, caller, transaction-signature, provenance-digest, secret, lookup-mapping fields, or other mapping material. New Bark observations discard the raw source profile before persistence, and startup sanitizes legacy Bark callout/event payloads. Feed-supplied creator/deployer evidence may remain in the private token database for the bounded prospective history calculation, but only opaque labels and aggregate counts are public.

The early-actor worker queries only exact public mints already admitted by this War Room through bounded finalized public Solana RPC requests. Raw wallet addresses, transaction signatures, RPC responses, source payloads, and reversible lookup mappings are not persisted in actor tables. A domain-separated keyed dedupe digest derived from internal transaction provenance is stored with each minimized observation only to reject duplicates; it is not a public identifier or lookup mapping, is never returned, and expires with that observation. Minimized normalized events otherwise retain only an opaque Actor label, validated side, bounded amounts, evidence class, source/observation timestamps, and a non-identifying slot number. Independent time-driven cleanup expires those events after at most 72 hours and also enforces a global 4,096-row bound; per-mint aggregate evidence can remain with the fixed 32-mint cohort for auditability. The installation secret remains owner-only in SQLite so labels survive restart and a verified restore drill. It is never returned by a public endpoint.

Sharing and sale

The application does not sell personal information. Data may be processed by the configured hosting and upstream data providers only as needed to operate the service, comply with law, or protect security.

Retention and security

Application records—including sanitized material events, opaque actor aggregates, delivery state, and frozen measured briefs—are retained for operational research and recovery, subject to provider rights and deletion requirements. Database files are owner-only, and the linked Railway production volume is covered by Railway's stated AES-256 encryption at rest. Access is limited to the service operator and configured infrastructure. A provider purge requires exclusive database access, removes provider-derived events, alerts, and briefs, uses SQLite secure deletion and vacuuming, and verifies WAL cleanup; separate backups must be securely deleted independently. No internet service can promise absolute security.

Telegram recipients can stop or block the bot; the operator can disable delivery by removing its Telegram configuration and can delete retained delivery evidence through a reviewed database operation. Questions about access, deletion, opt out, or this notice should be directed to the service operator through the same channel that provided access. Rights vary by location and will be honored where applicable.
