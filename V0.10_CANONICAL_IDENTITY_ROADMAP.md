# v0.10 Canonical Identity Graph roadmap

Status: **M1–M3 release-verified in v0.10.1; M4 implemented in v0.10.3; verifier timing hardened in v0.10.4**

v0.10 is an additive identity-infrastructure track. It does not satisfy, weaken, or reset the separately documented v1.0 gate requiring at least 30 days of trustworthy live data, calibrated outcomes, monitoring, verified backups, and documented recovery.

## Product contract

Resolve any exact Solana mint into a stable entity envelope while preserving the mint as the immutable identity boundary. Cross-mint relationships are typed, evidence-backed, timestamped, and reviewable. Matching names, symbols, images, narratives, or social links never merge mints automatically.

The registry may describe identity and market selection. It must not claim safety, legitimacy, common control, maliciousness, or a trade recommendation.

## Milestones

### M0 — Contract bootstrap (implemented)

- Closed vocabularies for reviewed entity variants and cross-mint relationships.
- Exact-mint singleton fallback for every valid Solana mint.
- Reviewed-registry resolution with explicit or withheld primary selection.
- Public read-only resolver endpoint and coin-dossier dogfooding.
- Focused validation and non-merging tests.

Acceptance: invalid mints and duplicate ownership fail closed; same-name singleton mints remain distinct; ambiguous multi-variant entities expose no primary mint.

### M1 — Persistent review ledger (implemented)

- Add versioned SQLite tables for entities, variants, relationships, evidence, and review decisions.
- Preserve append-only decision provenance; corrections supersede prior decisions instead of rewriting them.
- Extend backup, restore, exact-schema, privacy, and purge verification before production use.
- Provide local operator import/export with bounded, allowlisted JSON; no unauthenticated public writes.

Acceptance: restart and disposable restore preserve byte-equivalent public resolutions and decision history; malformed or secret-bearing evidence is rejected.

### M2 — Candidate proposal engine (implemented)

- Generate proposals from already-authorized evidence only: exact creator/deployer observations, processed migration evidence, normalized public metadata, and reviewed official links.
- Keep proposals separate from verified registry state.
- Never scrape Pump.fun or Fomo, inspect private endpoints, or replay authenticated cookies.
- Deduplicate proposals deterministically and retain explicit missing evidence.

Acceptance: automation cannot publish a verified relationship or primary mint; replay produces the same proposal keys; name/symbol/image similarity alone cannot exceed `name-collision` or `same-narrative` proposal status.

### M3 — Curator workflow and identity graph UI (implemented)

- Add an authenticated/local operator review queue for accept, reject, supersede, and split decisions.
- Add an Identity Graph panel to coin dossiers and comparison views.
- Show relationship kind, review state, evidence class, observation time, primary-selection reason, and limitations.
- Keep public surfaces read-only.

Acceptance: desktop/mobile visual QA passes; every public edge traces to a retained reviewed decision; rejected proposals never appear as facts.

### M4 — Entity-level intelligence and public API hardening (implemented)

- Aggregate narrative and lifecycle observations by entity without losing per-mint denominators.
- Prevent clone volume from inflating entity-level trending.
- Add pagination, API documentation, rate limits, health counters, and resolver smoke coverage.
- Dogfood the public contract throughout Pump War Room before offering external API keys.

Acceptance: mint-level results remain reproducible; entity aggregates disclose included/excluded variants and missing coverage; ranking remains independent of unreviewed identity proposals.

## Release gate

v0.10 may be production-released only after M1–M3 pass full tests, privacy/adversarial review, database backup/restore verification, desktop/mobile QA, and strict public smoke. M4 may follow as v0.10.x if the core registry ships first.

v0.10.1 release evidence: 336 tests pass; schema 902 backup/restore tests preserve nonzero identity facts, proposals, and decisions; adversarial smoke rejects public writes, automated verification, proposal/fact conflation, and a pending backlog above 500; desktop/mobile dashboard and dossier screenshots were inspected; and the local strict smoke passed with the read-only resolver and legal markers. The production rollout additionally requires a verified pre-migration schema-901 backup and successful public live smoke.

v0.10.3 completes M4 additively without a provider, dependency, schema, or external-key change. Reviewed entities expose included/excluded exact-mint denominators and narrative/lifecycle/volume missing states. Every trend uses at most one exact-mint contributor: grouped entities require one observed reviewed primary or sole reviewed variant, while unreviewed singletons remain separate; ambiguous multi-variant entities withhold metrics instead of summing clones. Stable entity-ID cursor pages, static OpenAPI 3.1 documentation, process-global per-instance rate bounds and aggregate counters, decoded-32-byte mint validation, bounded whole-entity projections, resolver/list smoke, ranking invariance tests, and dashboard/analyst contract dogfooding complete the milestone. Production verification still requires the normal full-suite, privacy/adversarial, backup/restore, responsive QA, strict smoke, and single-rollout gates.

v0.10.4 versions the post-release verifier timing corrections. Cached token-integrity freshness and rate-limit reset windows are evaluated at each response's receipt time instead of after the verifier finishes later endpoint checks, preventing valid evidence from failing only because the smoke traversal itself took longer than its validation window. Smoke fixtures derive their expected version from canonical package metadata instead of retaining a duplicate release literal. It changes no runtime data contract, schema, provider, dependency, intelligence, or product boundary.
